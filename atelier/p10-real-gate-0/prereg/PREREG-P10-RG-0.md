## 1. The target and its declared obligation

**Target:** probe [12] of `ml0-block-proof.lisp` (l.765–785): over `do-external-symbols` of `lisp-plus-memory-layer0`, for each `fboundp` symbol, `(handler-case (sb-introspect:function-lambda-list symbol) (error () nil))`, offender iff the arglist contains a symbol named `DEFECT` or `DEFECT-PAYLOAD`; `(probe "F1 · NO EXTERNAL FUNCTION … `DEFECT` PARAMETER …" (null offenders) <note>)`, note on CLOSED = the fixed literal *"walked every external fbound symbol's compiled lambda list"*.

**Declared obligation (the only one):** no external fbound function carries a `DEFECT`/`DEFECT-PAYLOAD` parameter (SPEC l.292–297 states the property and names F1 its checker). **Coverage claims, all non-normative:** header l.48–51 and l.761–764, the CLOSED note l.785, RETURN l.1326–1331 ("walks every external fbound symbol"). **No normative clause requires F1 to be complete or to report an uninspected symbol** (SOURCE-MAP §4, search recorded). **No calling-convention/signature obligation exists anywhere in F1 or the loader** (SOURCE-MAP §1: the loader probes `fboundp`/`boundp`/type only; lambda lists never).

**Why these mutations are relevant:** they are the three ways the walk can fail to see what it claims to see — a symbol it never reaches (absent binding: skipped by `(when (fboundp …))`), a symbol it reaches whose arglist it cannot read (error → `nil` → innocence), and the one thing it *does* declare it detects (an offender parameter) — plus the composite that decides whether non-observation masks an offender.

## 4. How the mutation is witnessed to have survived loading and reached the check

Every mutated subject gets a **witness process** (fresh `sbcl --script`, same subject, cwd = subject root) that loads `ml0-suite-ground.lisp` under `handler-case` (so a loader refusal is *captured and printed*, not fatal), then prints for the target symbol: `find-symbol` status, `fboundp`, and `function-lambda-list` (or the error). The witness's exit is 0 iff it printed its `WITNESS:` line. A case whose witness does not show the intended state is **INVALID** (the mutation did not survive loading), never PASS. For the interposer arms the exit-hook counts are the witness that the interposition was in the gate's process (`CALLS` ≠ 0) and reached the target (`TARGET-INJECTIONS` = 1 where intended, 0 on the control).

## 5. Per-case outcome classes and the auditor's verdict

The runner (`harness/p10-runner.sh`) → classifier (`harness/p10-classify.sh <case-dir> <expected>`): reads `gate.out.txt`, `gate.err.txt`, `gate.exit.txt`, (`witness.out.txt`, `witness.exit.txt`), (`interposer counts`), assigns ONE class, compares to `EXPECTATIONS-P10.txt`, prints `PASS <case>: <class>` / `FAIL <case>: got '<class>' expected '<expected>'` / `INVALID <case>: witness …` / `BLOCKED <case>: …`. Summary `P10-RUNNER: pass=<n> fail=<n> invalid=<n> blocked=<n>`; exit 0 iff fail=invalid=0 and every BLOCKED was expected. **Strictness (Astra §4, fixing the P8 runner's permissive paths, none inherited):** pinned list REQUIRED (absent → refuse, exit 5); prereg hash mismatch → REFUSE (exit 5), not warn; exactly one sentinel and one `[12]` line or `INCOHERENT`; class and exit must cohere (a green sentinel with exit ≠ 0 is `INCOHERENT` → FAIL); a witness that fails → INVALID; duplicate/absent expectation rows → refuse; a late error after the sentinel (`Unhandled` on stderr after a sentinel) → `INCOHERENT`.

**Controls of the verdict (each a full runner invocation with the override printed verbatim, or a synthetic case dir fed to the classifier):** C-1 `M2-P=GATE-GREEN` → `FAIL M2-P: got 'GATE-OPEN-F1' …`, exit 1. C-2 `M1-C=GATE-GREEN` → `FAIL M1-C: got 'BLOCKED-AT-LOADER' …` (a failure before gate entry cannot read as green), exit 1. C-3 synthetic dir: B0's stdout with `EXIT 1` → classifier `INCOHERENT` → `FAIL`, exit 1 (a success marker with an unexpected nonzero exit cannot pass). C-4 synthetic: M1-U's transcript with the witness line removed → `INVALID`, exit 1. These validate this experiment's classifier only.

## 6. VOID / INVALID / BLOCKED conditions

VOID: pinned closure mismatch on any subject before mutation; two runner processes at once; any write into the checkout. INVALID (per case): witness contradicts the intended state. BLOCKED (per case): a failure before the gate's first probe that is NOT the M1-C expectation (e.g. a missing SBCL contrib, a path error) — reported with its cause, never as detection.

## 7. What no outcome may become

No outcome certifies the gate, discharges the strict-stranger arm (Sol II's NOT TESTED BY THE STRICT STRANGER stands), amends the adopted P10 register, or changes F1's policy. If U1-M shows masking (expected), the return names the exact promise (the printed note; the SPEC property as "checked by a gate") and stops at diagnosis with a scoped recommendation — count and name uninspectable symbols; treat them as OPEN or as explicit PARTIAL under a separate disposition. The travelling clause **NO SUPPORTED-PATH RUNTIME SEMANTIC FAILURE ESTABLISHED** is untouched: F1 is a test instrument, and nothing here is about the runtime.
