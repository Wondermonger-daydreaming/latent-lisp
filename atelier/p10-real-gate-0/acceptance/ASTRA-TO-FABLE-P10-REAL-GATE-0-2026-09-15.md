## 3. Preregister a small, discriminating experiment

After identifying the source and before building or executing the fault cases, freeze a short preregistration naming:

- The exact target, declared obligation, and why the chosen mutation is relevant.
- The intervention point relative to dependency loading and gate inspection.
- Expected gate observations, verdict and exit behavior; distinguish a source-supported expectation from an exploratory question.
- How you will independently witness that the mutation survived loading and reached the intended check.
- Per-case outcome classes and the conditions that make the experiment blocked or invalid.

Use the following case family. Combine redundant cases only with an explicit source-based reason.

| Case | Intervention | Question |
|---|---|---|
| B0 — baseline | Unmodified pinned subject through the normal gate | What does a successful ordinary run actually inspect and report? |
| M1 — absent binding | Remove one binding that the real gate declares it checks, in an isolated subject/process | Does this gate detect the selected absence and propagate it to its actual verdict? |
| M2 — readable signature mismatch | Keep a selected function bound but give it a deliberately incompatible, inspectable lambda list relative to a declared check | Does the gate distinguish existence from the checked calling convention? |
| U1 — inspection unavailable | Reproduce FRIGUS's uninspected-lambda-list condition, or a precisely documented intervention at that inspection boundary | Is non-observation exposed as a skip/partial result, treated as success, or rejected? |

M2 applies only if the real instrument declares a relevant signature obligation. If none exists, document that boundary rather than inventing an obligation. U1 is an experiment about reporting and coverage; a green aggregate under an explicitly partial contract is not automatically a bug.

A source error, missing loader, or runtime crash before F1 reaches the selected target is BLOCKED, not a successful detection. A load that silently restores an absent binding has invalidated M1. Prove which occurred.

Run in fresh processes and distinct run directories. Establish an unmodified control under the same intervention mechanism so that the mechanism itself is not mistaken for detection. Restore by discarding the disposable subject and checking the pinned source identities.
