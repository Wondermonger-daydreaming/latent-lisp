### 2a. The phase-partitioned gate-check predicates

**What changed, exactly.** Two R3.3-era checks —
`INIT-STALE-CLEAN-NO-PARTIAL-STATE-OBSERVED` and
`INIT-RECURSIVE-NO-PARTIAL-READY-OBSERVED` — replaced

```lisp
(and (every (lambda (e) (null (third e))) (sa0-pre-publication-entries  *sa0-phase-log*))
     (every (lambda (e) (eq t  (third e))) (sa0-post-publication-entries *sa0-phase-log*)))
```

where `*sa0-post-publication-phases*` is `'(:published-before-return)`
(`probe-init-schedule.lisp:222-229`).

**Identity, position, profile — checked, not assumed.**

- **IDs:** both `probe-check` ID strings are byte-unchanged in the diff.
- **Positions:** `verify-sequences.txt` is **additive only** — the `init-stale`
  and `init-recursive` blocks are untouched, so both checks keep their ordinal
  position in their section's mandated sequence.
- **Profiles:** `verify-profiles.txt` still reads `init-stale
  INIT-STALE-SCHEDULE:0:12` and `init-recursive INIT-RECURSIVE-LOAD:0:11`;
  neither row is in the diff. Confirmed against the dev evidence: `final1.log`
  verifies `profile=init-stale … checks=12` and `profile=init-recursive …
  checks=11`.
- One **label** did move: the recursive check's prose was reworded from "Every
  gate observation in this image reports ready-p NIL" to "Every gate observation
  taken BEFORE the one publication reports ready-p NIL, every observation taken
  after it reports T". The grammar anchors these sections on `CHECK-ID` lines
  only, so no sequence or profile is affected — but this is a **text change
  inside a locked seam's transcript**, and it is the chair's and the owner's to
  dispose, not mine.

**Is the amendment genuinely strictly stronger? — the exact answer.**

Write `O(L)` for the old formula and `N(L)` for the new, over a gate log `L`
partitioned into pre-publication entries `P` and post-publication entries `Q`:

- `O(L) ≡ ∀e∈P: ready(e)=NIL ∧ ∀e∈Q: ready(e)=NIL`
- `N(L) ≡ ∀e∈P: ready(e)=NIL ∧ ∀e∈Q: ready(e)=T`

Three statements, all true, and only the first two are what the disclosure
should have said:

1. **On the pre-publication partition the two formulas are IDENTICAL.** Every
   observation that could exhibit the hazard the seam exists to catch — a
   partially-ready image seen before the one publication — is refused by `N`
   exactly as it was by `O`. **No protective content was lost.**
2. **`N` adds a conjunct `O` did not have**, and it is a real new failure mode:
   a post-publication observation that did *not* see the state now fails the
   check. In that sense the amendment strengthens.
3. **`N` does not imply `O` over arbitrary logs, and the source's sentence
   "Nothing that the old predicate refused is now admitted" is, read literally,
   FALSE.** `O` refused any log containing an entry with `ready-p` T; `N` admits
   exactly that entry when its phase is `:PUBLISHED-BEFORE-RETURN` — which is
   precisely the case the amendment exists to admit. The two formulas are not
   ordered by strength; on logs where `Q` is nonempty they are **mutually
   exclusive**.

The reconciliation, which I checked rather than assumed: under R3.3.1 the
candidate source declared five phases — `:OBSERVED-PRE-INITIAL`,
`:OBSERVED-CARRIER-PLIST`, `:ELECTED-BEFORE-NOTE`,
`:ELECTED-BEFORE-PUBLICATION`, `:BEFORE-WAIT` — **all of them pre-publication**.
So `Q` was empty for every log the old predicate could ever receive, and on that
whole reachable domain `N ≡ O`. The old formula did not *cover* the
post-publication case; it was **vacuous** on it.

**Finding (a), rendered for disposal.** The amendment is *substantively* what
the disclosure claims — the locked seams' protection is preserved verbatim on
every entry class that existed, and a new obligation is added — and its
*wording* over-reaches by one sentence. The precise true sentence is: **equal to
the old predicate on the phase inventory that existed when the old predicate was
written, plus a new requirement on a phase class that did not exist.** Recorded
as **GAP-2** below because a written claim that is not literally true is the
class this lane repairs rather than carries; the mechanism itself needs nothing.

**Under "freeze every existing accepted profile and repair": did any locked
seam's semantics weaken?** No. The hazard is a partially-ready observation
*before* publication; every pre-publication phase must still report `NIL`. What
weakened is nothing; what moved is one label's prose and one formula's coverage
of a case that could not previously arise.

**One coupling worth naming, non-blocking.** `*sa0-post-publication-phases*` is
a harness-side *mirror* of the candidate source's phase table (the source is
declared the authority at `218-220`). If a future round adds a post-publication
phase to the source and forgets this list, the new phase falls into the *pre*
partition and is required to report `NIL` — it would **fail**, not silently
pass. The coupling fails closed. Recorded, not charged.

### 2b. The five-arms-one-image carrier-slot design and its zero-election argument

**The argument as printed** (`1213-1221`, and again in `run-probe.sh:341-348` and
the transcript's own scope block): the other roles each need an image in which a
first initialization can still be scheduled and each spends that moment; **a
rejected load spends nothing** — it refuses before any election is attempted, so
it installs no cell, notes no election and gathers no epoch; therefore four
refusal arms may share one image, the lawful arm runs last, and it is the only
arm that spends the moment.

**Is it sound? — traced, and the contested step shown.** The load reaches the
initialization form `(sa0-initialize-image-identity)` at `probe-identity.lisp:1009`,
whose first act is `(sa0-carrier-cell)` → `SA0-SCAN-RESERVED` →
`SA0-ADJUDICATE-RESERVED`. On each of the four planted carriers the adjudicator
signals **before** `SA0-STAND-FOR-ELECTION` is entered, so `SA0-INSTALL-CARRIER`
is never called, `SA0-NOTE-ELECTION` is never called, and no `ATOMIC-PUSH` onto
`GATHER-MARKS` occurs. **The rejection is upstream of every state-consuming
operation**, and that is the load-bearing step.

Three residues I looked for, since "spends nothing" is a claim about the whole
image and not only about the election:

1. **The election log** lives on `(symbol-plist 'sa0-identity-election-log)` and
   is only appended by `SA0-NOTE-ELECTION`, which no rejected arm reaches. The
   arm does not rely on that argument: it **prints** `elections before the
   lawful arm 0` and the lawful check asserts `(eql 0 *cs-elections-before-lawful*)`.
   Measured, not assumed — which is the right shape.
2. **Redefinition residue.** Each arm re-`LOAD`s the same file, so the defuns are
   re-evaluated. The file uses simple vectors, not `DEFSTRUCT`, and defines no
   condition class, so there is no layout-redefinition hazard; the re-evaluated
   definitions are identical text.
3. **`*sa0-identity-source*`** (`1017`) is a `DEFPARAMETER` that sits *after* the
   initialization form, so a rejected load never reaches it — it is set for the
   first time by the lawful arm. No stale value can be inherited.

**Verdict on (b): the argument is SOUND**, and better than sound in method — the
one quantity it turns on (elections held before the lawful arm) is printed and
asserted rather than argued. Two honest limits, both already disclosed in the
section: the lawful arm is the fifth `LOAD` in its image rather than the first,
so what it re-asserts is the ordinary path *in an image where four loads were
refused*, not a virgin-image first initialization; and the harness writes the
carrier symbol directly (`sa0-cs-set-carrier`), which is exactly the "foreign
agent" the source's own ceiling paragraph (`333-338`) excludes from its
guarantees — appropriate for a tooth that must plant states, and named here so
no reader takes the plants as counter-examples to the CAS discipline.
