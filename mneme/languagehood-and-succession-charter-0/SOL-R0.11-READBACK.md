## 5. Readback findings

### SOL-R11-01 — RATIFICATION BLOCKER — raw-HTML comments can hide a Status column

Fixture:

```markdown
Claim | <!-- a > b -->Status | Note
--- | --- | ---
r1 | **MYSTERY** | hidden column
```

This is a valid GFM table. The header's second cell renders visibly as
`Status`: `<!-- a > b -->` is an HTML comment and contributes no visible label.
GFM comments terminate at `-->`, not at the first internal `>`; the comment
text above satisfies the comment grammar. GFM defines comments, processing
instructions, declarations, and CDATA alongside open/close tags as raw HTML.
See the [GFM raw-HTML grammar](https://github.github.com/gfm/#raw-html).

v10 instead applies:

```python
HTML_TAG = re.compile(r'''<(?:[^>"']|"[^"]*"|'[^']*')*>''')
```

That expression consumes only `<!-- a >`, leaving ` b -->Status`. The plain
projection therefore does not start with `status`; neither the column detector
nor the conservative guard sees the cell.

Actual ordinary invocation under a matched `0:0` expectation:

```text
0 declarations, 0 table status cells
CLEAN
exit 0
```

A companion interaction is equally direct:

```markdown
Status | <!-- a > b -->Status | Claim
--- | --- | ---
**OPEN** | **MYSTERY** | r1
```

v10 counts the first Status cell, ignores the second column, reports one clean
cell, and exits 0. Thus the direct first-match repair is real, but “every
projected Status-like column” is not yet enforced.

**Consequence:** a governed table can carry an unchecked Status column and a
non-legend primary while retaining a green validator result.

### SOL-R11-02 — RATIFICATION BLOCKER — shortcut reference links hide a second strong primary

Fixture:

```markdown
Claim | Status | Note
--- | --- | ---
r1 | **OPEN** / __[HISTORICAL]__ | second primary

[HISTORICAL]: https://example.com/history
```

GFM defines full, collapsed, and shortcut reference links. A shortcut
reference such as `[HISTORICAL]`, when its definition exists, renders visible
link text `HISTORICAL`. See [GFM links, shortcut-reference
form](https://github.github.com/gfm/#links).

The complete second strong node therefore renders as the primary legend
`HISTORICAL`. v10's `strong_label()` reduces inline links and two-bracket
reference forms, but not shortcut references. The brackets survive, so
`is_primary_legend()` compares `[HISTORICAL]` rather than `HISTORICAL`.

Actual ordinary invocation:

```text
0 declarations, 1 table status cell
CLEAN
exit 0
```

**Consequence:** the exact-one-primary guarantee is still false for standard
GFM strong content.

### SOL-R11-03 — RATIFICATION BLOCKER — prose declarations have no exact-one enforcement

Fixture:

```markdown
**Status: OPEN** / **HISTORICAL**
```

Both strong nodes are plain, unambiguous Markdown. The line asserts two primary
legends for one prose declaration. v10 parses the first `Status: OPEN` token,
validates `OPEN`, and performs no second-primary scan over the remainder of a
prose declaration.

Actual ordinary invocation:

```text
1 declaration, 0 table status cells
CLEAN
exit 0
```

This defect requires no exotic inline construction. It is a missing semantic
rule: table cells receive exact-one enforcement; prose declarations do not.

**Consequence:** a classified prose proposition can carry contradictory primary
statuses while the validator certifies it clean.
