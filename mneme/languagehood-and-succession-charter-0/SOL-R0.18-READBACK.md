## 6. SOL-R18-01 — the source repertoire is not actually closed

**Classification:** enforcement bypass; absent from governed corpus; one finite source-law root.

P2 refuses Unicode categories `Cf`, `Co`, and almost all `Cc`. P2b then refuses non-ASCII characters only when their category begins with `L`, except for the declared Greek letters α, β, and δ.

That leaves non-letter default-ignorable marks admitted. Two ordinary-file witnesses demonstrate the property:

1. `Sta\u034Ftus` — U+034F COMBINING GRAPHEME JOINER;
2. `Sta\uFE00tus` — U+FE00 VARIATION SELECTOR-1.

For each witness:

- the whole source is already NFC;
- the inserted character is Unicode category `Mn`, not `Cf`, `Co`, `Cc`, or `L*`;
- the inserted character is visually default-ignorable;
- the strong source presents to a reader as `Status: MYSTERY`;
- the checker reports **0 declarations, 0 table status cells, CLEAN, exit 0**.

The cause is not a missing rendering algorithm. It is simpler: the declared border admits characters it has assigned no lexical role. P2b is described as a “closed alphabet,” but it closes only the subset of code points whose Unicode category is a letter.

The five governed files contain **no Unicode mark characters at all**. Their non-ASCII source repertoire is already finite: eighteen distinct code points, all known.

### Required repair

Do not add another category heuristic. Replace the category-based partial closure with an exact admitted source repertoire:

- horizontal tab U+0009;
- line feed U+000A;
- printable ASCII U+0020–U+007E;
- and exactly these eighteen non-ASCII code points already used by the governed five-file corpus:

|---|---:|---|
| U+00A7 | § | SECTION SIGN |
