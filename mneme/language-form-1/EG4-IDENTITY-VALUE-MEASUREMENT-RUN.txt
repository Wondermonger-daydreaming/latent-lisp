---- (c) THE CLIFF: declarations past the envelope ----
  A host supplies ONE oversized declaration.  Three questions, all
  answered by running it rather than by reasoning about it:
    WHERE does it refuse · WITH WHAT CODE · was DERIVE/2 invoked?

  A NOTE ON HOW THIS BLOCK WAS WRITTEN.  Its first draft asserted in
  prose that an oversized declaration is discovered only at SUBMIT and
  that `no earlier gate warns of it'.  Running it refuted that in one
  line: at 70,000 octets the refusal fires at SEAL-RESOLUTION-CONTEXT.
  The prose was a claim wearing a measurement's clothes.  The table
  below replaced it, and the retraction is left visible on purpose.

  declaration   1000 → decl-identity 1287    · ctx-occurrence 1403    · refused at :COMPLETED  :GRANTED                           · DERIVE/2 1
  declaration  20000 → decl-identity 20289   · ctx-occurrence 20407   · refused at :COMPLETED  :GRANTED                           · DERIVE/2 1
  declaration  55000 → decl-identity 55289   · ctx-occurrence 55407   · refused at :COMPLETED  :GRANTED                           · DERIVE/2 1
  declaration  61000 → decl-identity 61289   · ctx-occurrence 61407   · refused at :SUBMIT     :SUBMISSION-ENVELOPE-EXCEEDED      · DERIVE/2 0
  declaration  64000 → decl-identity 64289   · ctx-occurrence 64407   · refused at :SUBMIT     :SUBMISSION-ENVELOPE-EXCEEDED      · DERIVE/2 0
  declaration  70000 → decl-identity —       · ctx-occurrence —       · refused at :CONTEXT    :IDENTITY-OCTETS-EXCEEDED          · DERIVE/2 0

  WHAT THE TABLE SHOWS, and it is better news than the first draft claimed:

  THERE ARE TWO PRE-INVOCATION GATES, NOT ONE.
    · SEAL-RESOLUTION-CONTEXT gates the context DECLARATION and
      OCCURRENCE identities as it mints them, refusing
      :IDENTITY-OCTETS-EXCEEDED at phase :CONTEXT.  The context is
      never even built, so no petition can be submitted with it.
    · SUBMIT-PETITION gates the SUBMISSION OCCURRENCE identity PLUS the
      reserved outcome tail, refusing :SUBMISSION-ENVELOPE-EXCEEDED.

  IN EVERY REFUSING ROW, DERIVE/2 WAS INVOKED ZERO TIMES.  That is the
  policy v2 ordering repair still holding under v3: a resource ceiling
  refuses BEFORE the governed act, never after it, so no ceiling can
  erase an act that already happened.

  THE RESIDUAL, NAMED AT ITS TRUE (SMALLER) SIZE:
    There is still no policy ceiling on declaration size AS SUCH — no
    MAX-DECLARATION-OCTETS beside the four existing ceilings.  What
    bounds it is the identity envelope, enforced at seal and again at
    submit.  The practical consequence is narrow and worth stating: a
    host learns its declarations are too large only when it SEALS,
    which is after every binder has already accepted them.  The gap
    between `the binder took it' and `the seal refuses' is one call.
    Whether that warrants a fifth ceiling is a POLICY decision this
    review was not authorised to take.  It is measured, named, and
    left to the owner.

  AND THE HEADROOM, WHICH THE OWNER SHOULD SEE:
    policy v2, worst-case fixture   15882 / 65536   = 4.13x
    policy v3, governed-identity declarations       ~2.0x
    policy v3, worst-case fixture   60873 / 65536   = 1.08x
    The envelope was chosen under v2 when the worst case was 3.8x below
    it.  It is now 7 percent below it on the same fixture.  EG-4 HOLDS,
    measured, not assumed — but the margin is no longer generous, and
    calling it generous would be the flinch this lane is named for.
